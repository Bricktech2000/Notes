> Short version: there isn't a standard name for `mu x. a * f x` on its own, because for most functors `f` it's uninhabited.
>
> **mu vs nu, quickly:**
>
> - `mu x. F x` is the _least_ fixed point — the initial algebra of `F`. Its inhabitants are exactly the values you can build in finitely many steps (via a fold/catamorphism). No infinite values allowed, ever.
> - `nu x. F x` is the _greatest_ fixed point — the terminal coalgebra of `F`. Its inhabitants are values defined by how they can be infinitely observed (via unfold/anamorphism). Finite values are still allowed, but so are infinite ones.
>
> So `nu` types are a superset: every finite `mu`-value is also a valid `nu`-value, but `nu` additionally admits infinite ones.
>
> **Why Cofree uses nu:**
>
> ```
> Cofree f a = nu x. a * f x
>            = a :< f x
> ```
>
> Comonads are meant to model "a value plus an unbounded/possibly-infinite context" — `duplicate`/`extend` need to keep working at every depth, and things like an infinite `Stream` (`Cofree Identity a`) or an infinite Moore machine (`Cofree ((->) b) a`) are the whole point. If you used `mu` here, you'd forbid exactly the interesting infinite cases.
>
> **What happens if you take `mu x. a * f x` instead:**
>
> To finish building a value, you eventually need to produce an `f x` with _no_ recursive occurrence of `x` left inside it — but a generic `f` has no way to do that (there's no "stop" case). So for a generic functor, this type is empty (isomorphic to `Void`), because product forces you to go one level deeper forever, and `mu` won't let you go forever.
>
> It only becomes non-trivial when `f` itself has a built-in termination case:
>
> - `f = Maybe`: `mu x. a * Maybe x` ≅ `NonEmpty a`
> - `f = []`: `mu x. a * [x]` ≅ finite, well-founded rose trees (as opposed to `Cofree [] a`, which additionally permits infinitely deep/branching trees)
> - `f = Either e`: gives you finite chains terminating in an `e`
>
> So the "mu-Cofree" isn't really its own concept — it degenerates into whatever finite structure `f`'s base case implies. In Haskell specifically you don't usually notice this distinction because laziness means `Cofree f a` (defined coinductively) already contains all the finite trees too; the `mu`/`nu` split only bites in a total/strict setting like Agda or Idris, where `data` (inductive) and `codata`/`Thunk` (coinductive) are genuinely different types.

> Nice catch — let's push the calculus through carefully, because the two computations aren't _quite_ identical, and the discrepancy is exactly where the Free/Cofree duality shows up.
>
> **Redo both derivatives via implicit differentiation**
>
> For `T = mu x. a * f x`, we have `T = a·f(T)`. Differentiating w.r.t. `a`:
>
> ```
> dT/da = f(T) + a·f'(T)·(dT/da)
> dT/da = f(T) / (1 - a·f'(T))
> ```
>
> At `a=1`, `T(1)` solves `x = f x`, i.e. `T(1) = Mu f`. So
>
> ```
> dT/da |_{a=1} = f(Mu f) · List(∂f(Mu f))
> ```
>
> For `T' = mu x. a + f x` (Free), `T' = a + f(T')`, giving
>
> ```
> dT'/da = 1 + f'(T')·(dT'/da)
> dT'/da = List(f'(T'))
> ```
>
> At `a=0`, `T'(0)` also solves `x = f x`, so `T'(0) = Mu f`, and
>
> ```
> dT'/da |_{a=0} = List(∂f(Mu f))
> ```
>
> **Why they look almost the same:** by Lambek's lemma, `f(Mu f) ≅ Mu f`. So the product case is `Mu f · List(∂f(Mu f))` — that's a zipper _location_: a focused subtree paired with the path up to root. The sum case is just `List(∂f(Mu f))` — the _bare path_, with no focus, because a hole at a leaf (an `a`-slot in a sum) has nothing sitting "inside" it the way a hole in a product leaves the other factor `f(x)` behind. So really: product-mu differentiates to _zipper-with-focus_, sum-mu differentiates to _zipper-context-alone_. Colloquially people call both "the zipper," which is fine since they only differ by whether you carry the pointed subtree.
>
> **The deeper reason they coincide:** differentiation is about isolating one distinguished occurrence of `a` and discarding everything that isn't on the path to it. In a sum, the other branch simply isn't there when you're differentiating along this one; in a product, the other factor is still there but it's _not itself under the derivative_, so recursion doesn't touch it beyond one layer. Either way, once you strip off the first layer, what governs the recursive shape is `∂f`, not `+` or `*` — the sum/product distinction that separates Free from (finite) Cofree lives entirely in "what's attached to a node," and a path/zipper has already thrown that away in favor of "which child did I descend through." That's the real reason both collapse to `List(∂f(Mu f))`.
>
> **Connection to Cofree comonads — yes, directly:**
>
> Zippers are the standard example of a comonad (`extract` = current focus, `duplicate` = "recompute the whole zipper as if focused at every reachable position"). You can build that comonad explicitly as a `Cofree`-structure, but over `∂f`, not over `f` itself. Concretely: take `Mu f` and annotate _every node_ with its own path-from-root. That annotated tree satisfies
>
> ```
> Z(path) = (path, f-shaped collection of Z(path ++ [one-step context]))
> ```
>
> which is exactly the unfolding of `Cofree f b` with `b = List(∂f(Mu f))`, seeded by growing the path with one `∂f`-context per step down. So: the comonad you get by pairing every node of `Mu f` with its own zipper is `Cofree f (List (∂f (Mu f)))`, built via the derivative at each layer.
>
> So the picture ties together like this:
>
> - `mu x. a + f x` = Free monad, initial-algebra flavor, sum-shaped.
> - `mu x. a * f x` (finite version) = "finite Cofree," terminal-coalgebra flavor generalized to product-shaped, but bounded.
> - Differentiating either at the fixed point where `x = f x` produces the same skeleton `List(∂f(Mu f))`, because a path is inherently linear regardless of whether the type it came from was built with `+` or `*`.
> - Re-decorating `Mu f` with that path data everywhere gives you back an honest `Cofree f`-comonad — so the zipper isn't just _analogous_ to Cofree, it's literally how you manufacture the canonical Cofree comonad over `f`, using `∂f` as the engine.

> **Derivative of `nu x. a * f x`:**
>
> Implicit differentiation doesn't care whether you're at `mu` or `nu` — the mechanics are identical:
>
> ```
> T = a·f(T)
> dT/da = f(T) / (1 - a·f'(T))
> ```
>
> At `a=1`, `T(1)` now solves `x = f x` in the _greatest_-fixed-point sense, i.e. `T(1) = Nu f` (possibly-infinite `f`-trees). By Lambek, `f(Nu f) ≅ Nu f`, so
>
> ```
> dT/da |_{a=1} = Nu f · List(∂f(Nu f))
> ```
>
> Same shape as before — `subtree * path` — but now the "subtree" and every node of `f(T)` visited along the derivation can be infinite. The key point: **the path itself is still finite.** Differentiation only ever isolates _one_ occurrence of `a`, so the walk from root to that occurrence is a finite `List`, even though the structure being walked through is coinductive. So yes — this is exactly a zipper into a `Cofree`/`Nu`-structure: a finite breadcrumb trail (`List(∂f(Nu f))`) paired with a (possibly infinite) focus (`Nu f`). This is precisely the shape you want for things like a cursor into an infinite `Stream` or a position in a Moore machine — finite navigation history, unbounded structure at and beyond the cursor.
>
> **On "zipper ≅ whole type":**
>
> I'd push back on this a bit — it's not a general theorem, and where it looks true it's usually a coincidence of a specific type, not a structural law.
>
> What's actually definitional is the **plug** map:
>
> ```
> plug : Context(T) * Subtree(T) -> T
> ```
>
> which reinserts the focused subtree into its context to recover a whole `T`. This map is a _surjection_, but it is essentially never injective: every node position in a given tree `t : T` gives you a different `(context, subtree)` pair that plugs back into the _same_ `t`. So the honest relationship is
>
> ```
> Locations(T) ≅ Σ (t : T). (positions in t)
> ```
>
> i.e. `Locations(T)` is `T` weighted by its own node-count, not `T` itself. It only collapses to `T` when every value of `T` has exactly one position (degenerate).
>
> Concretely: the zipper of `List(A)` is `List(A) * List(A)` (context split around the cursor, roughly `(reversed prefix, suffix)`). That's not isomorphic to `List(A)` as a _canonical_ recursive type — e.g. `List(Void)` has one element (`[]`) with zero positions, so `Locations(List(Void))` is empty, while `List(Void)` itself is a singleton. Cardinalities can coincide for infinite carrier types (that's the `Nat × Stream(A) ≅ Stream(A)` flavor of accident you get with `nu`-types, via a pairing-function-style bijection), but that's a set-theoretic coincidence about countable cardinals, not something that holds structurally or that transports the comonad/monad operations.
>
> So: `path * subtree` is genuinely a different (bigger, pointed) type from `T` in general — it's `T`'s "one-hole-context bundle," and the fact that it sometimes has a bijection back to `T` (as in your `mu`/`nu` list examples) is special to those shapes rather than a consequence of differentiation per se.
